# ADR-0002: Документация как фундамент и языконезависимое ядро

## Статус

Accepted.

## Контекст

Rocket должен быть применим к downstream-проектам на разных языках. Если фреймворк начнёт
встраивать предположения конкретного языка в core rules, он перестанет быть универсальным.
Одновременно агентная разработка требует твёрдого основания: без canonical docs агент начинает
выдумывать поведение или следовать случайному состоянию кода.

## Решение

Считать документацию фундаментом Rocket:

- core Rocket определяет структуру правды, execution lifecycle, Git-модель, безопасность,
  память и reconstructability;
- язык продукта всегда объявляется в `engineering-profile.md` downstream-проекта;
- reusable поддержка конкретного языка добавляется как language pack/шаблон, а не как изменение
  базовых правил;
- feature docs описывают поведение независимо от языка реализации;
- код и тесты реализуют canonical docs, но не переопределяют их.

## Последствия

- Новый язык можно добавить без переписывания core standards.
- Downstream-проект обязан явно объявить команды bootstrap/run/test/build для своего стека.
- Language packs могут расширять удобство, но не могут ослаблять doc-first и reconstructability.
- Документация остаётся первым артефактом, по которому агент восстанавливает проект.

## Границы

- ADR не выбирает конкретный язык для downstream-проектов.
- ADR не вводит package manager, test runner или build system по умолчанию.
- ADR не запрещает самому Rocket использовать Babashka для собственной лёгкой автоматизации.
