# ADR-0001: Локальный Git и модель одного оператора

## Статус

Accepted.

## Контекст

Rocket — потомок более тяжёлого фреймворка, который строил координацию вокруг remote Git как
распределённого источника правды: ветки `dev`/`main`/`release/*`, freeze-окна релизов,
обязательный push рабочих веток, удалённые claim-локи, многохостовая безопасность. На практике
рантайм всё равно оставался single-host, а аппарат давал ложное чувство распределённости и
большую церемонию на каждую мелкую задачу.

Целевой пользователь Rocket — **один оператор**, работающий локально. Распределённый арбитраж,
релизные окна и принудительный push ему не нужны и только мешают.

## Решение

Принять **локальную, single-operator Git-модель**:

- `dev` — единственная интеграционная ветка и текущее рабочее состояние. Главная рабочая копия
  всегда на `dev`; запуск проекта берёт код из `dev`.
- Параллельная изоляция через **локальные** `work/<agent>/<task>` ветки и worktree — только
  когда работают несколько агентов. Один агент работает прямо в `dev`.
- Никаких `main`, `release/*`, `hotfix/*`, freeze-механики.
- Координация — локальные claim-локи (файлы на одном хосте). Distributed safety не заявляется.
- Push в remote, PR, публикация — **только по явной команде человека**. Фреймворк никогда не
  пушит сам.

## Последствия

- Обычная задача не требует push, удалённых веток и релизной церемонии.
- `dev` всегда запускаем и актуален — это инвариант, на который опирается оператор.
- Безопасность параллельной работы держится на непересекающихся `owned_modules`, а не на
  распределённых локах.
- Публикация в GitHub становится осознанным отдельным шагом, а не побочным эффектом цикла.

## Границы

- Эта модель не предназначена для multi-host или нескольких независимых операторов на разных
  машинах. Если такой сценарий возникнет, потребуется отдельный ADR.
- ADR не вводит автоматический push ни в каком виде.
